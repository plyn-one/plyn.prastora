# Site mode of the Prastora rendering checker

Prastora's public source checker is invoked through the **Plyń frame's own configured GitHub Actions runner** and the required `chromium` check on each commit. For a local synthetic site fixture, run `node check.mjs path/to/page.html --site` with Playwright Chromium installed. It also accepts deployed HTTP(S) addresses for reading the public page and linked core, but **a deployed site owned by another frame is accepted only through that owner's explicitly assigned Klučnik browser executor**. The source CI result is not a production-site acceptance.

`--site` allows author-owned `class`, inline style, local site stylesheets, unknown site-specific `data-*` and a headerless/footerless page, while still validating Prastora layout attributes, document language, title, exactly one `main`, one nonempty description, one absolute canonical without a fragment, hreflang URLs/duplicates, robots duplicates, image text, resources, visible target size, contrast and actual keyboard traversal. It checks portrait and landscape, light and dark, and print; `--extended` also samples frame edges and wide sizes. An optional locally installed `axe-core` may be enabled with `--axe`; `--html` validates local HTML with a configured `VNU_JAR` (not deployed URLs). Optional engines are not silently presumed installed.

`strict` (omit `--site`) retains the closed manifest, prohibits free site classes and styles and diagnoses unexpected document overflow and parent escapes. In site mode, overflow may be intentional in authored carousels or horizontal compositions, so it is not automatically rejected. The site owner still must verify intended scrolling and visual geometry; green source CI must not be interpreted as proof that all deployed page layouts are correct.

For a reference page, link its pinned Prastora core first, then any optional selected module CSS and the site's own stylesheet. Give semantic markup a document language, title, description, canonical and exactly one main. A page with `noindex` may still need valid descriptive metadata under the current checker. There is no generator of SEO, forms, translation, routing or publishing: those remain with the site and its backend.

The public regression test `check.test.mjs` covers a headerless branded example, strict-mode rejection of its free styling, good metadata and invalid metadata, remote HTTP use, intended scroll, keyboard traps, resources and strict-mode invariants. The optional `modules/modules.test.mjs` exercises independent Service and Editorial components. These are test fixtures, not a pinned release or proof of deployed acceptance.

# plyn.prastora

plyn.prastora: the web layout framework of Plyń, made first for agents: plain HTML and CSS in which a page keeps its composition across screens, with a closed vocabulary an agent reads whole and a check that renders a page and tells the agent what broke. The kernel is plyn-one/plyn, kept in one place and not copied here: the place is checked with the tool github_read of the frame's Klučnik, operation check, and landed with its tool github, operation land; each landed commit records, in its status pravierka, the kernel that passed it, and a new kernel rechecks this place by itself. śled.toml keeps what a commit does not: the cycles left open, each with what is expected, who judges, by what measure and where its answer comes, and the decisions no change carries, each with who took it; work done is told once, in its commit, and not again here. It is read through the matrix of the kernel (vyhlad.md of plyn-one/plyn). This file is written by plyn-one/plyn.dojlid (experiments/uvachod.py) from miesca.toml and these readings and is rewritten when the place changes; the norms of the system are read in plyn-one/plyn.mova.

Every text has one addressee, and its language follows from it, switching as the addressee changes. For Plyń: statements of formuła and words of the canon. For a project: the language of its readings, pračytańnie/<tag>.toml. For a person: the person's own language in ordinary words, with no word of the canon, no sign of formuła and no name from code unless the person uses them first, and then only those; what the system keeps in its own words is said to a person in theirs. To a person, answer the question asked, and only it: the answer first, then what it rests on if the person needs it to act; each thought once, in the fewest words that keep it clear; no restating the question, no recap of steps, no closing summary of what was just said. A text of a place addressed to a person is listed in its miesca.toml under adrasat.asoba, and norm adrasat.asoba holds it to that: no word of the canon, no sign of formuła. Assume the person is not a developer: do not hand them technical, access or security questions they cannot weigh; settle such questions by the system's checks or with other agents, and ask the person only about their own work and about steps that cannot be undone. Status meant for agents (a pilot, a test, a temporary arrangement) stays with agents and is not shown to a person, and nothing shown to a person helps an outsider guess how the system is guarded. Know what data you handle and where you write it. Data from open sources, published or meant to be shared, is open: it may be written in any place, names of people in it included, with no check before writing. Closed data, from a case, an applicant, a person's correspondence or private notes, is written in no repository, whoever may read it: it is kept only in the database of its frame, behind the frame's klucnik, and an agent reads and writes it there through the frame's tools. What becomes of data once it is prepared for an owner, closed as know-how, made anonymous or published, is the owner's decision.

Work is checked before each commit, and the check costs nothing on GitHub: with the tool github_read of the frame's Klučnik, operation check, naming the repository and the ref (the branch or commit the work starts from), and passing the files not yet committed as changes (a path to its new text, null for a file deleted); it runs the check Plynia runs, so its verdict is the one that decides, and needs no clone of the kernel. An agent that changes the kernel or the workshop runs the same check as `node --experimental-strip-types <kernel>/ts/cli.ts <this place>`. The tool github of the frame's Klučnik, operation land, naming the repository and the branch, lands its head on main: Plynia checks it and sets the status pravierka, and main takes it through the gateway, with no clone of the kernel or the workshop; when the change touches what the place's own tests guard (samapravierka.py, its paths under pravierka.šliach of miesca.toml), the agent runs them first and records what ran and its result in a trailer `Testy:` of the commit. An agent that changes the kernel or the workshop lands with `python3 -B <dojlid>/experiments/posadka_relay.py <this place>`, plyn-one/plyn.dojlid cloned once as <dojlid>, and the kernel only through its release. GitHub Actions runs no check of a place, and the kernel generates no workflow (norm prachod); minutes of Actions are kept for what has no other runner, such as an event of GitHub, and a check is never sent there to run. An agent reaches GitHub through the Klučnik of each frame it works in: the tools of its connection, and for git and GitHub's REST API the session pass that its operation git_access gives, set up once per session for each frame; it keeps no token of its own and does not use the GitHub command-line client gh. An agent that cannot run code checks and lands its change the same way, one commit on a branch; when the change touches what the place's own tests guard, it opens its pull request with what the check answered and asks in plyn-one/plyn.altanka for an agent that runs code to run them and land it. No agent pushes commit after commit to find out what passes. An agent changes a file with a tool that writes the text exactly as given, and reads the changed lines before it runs them. A commit names the cycle it serves with a trailer `Cełaść: <owner>/<repository>#<whole>`: once it lands, the landing marks the agent as working on that whole through the Klučnik of its account, and with zhoda or razychodžańnie after the number completes the whole's expectation, its vynik naming the commit; so the act an agent does anyway writes the journal (plyn-one/plyn.laba whole 445).

## What is here

- `pračytańnie/` (1.2 miaža): the readings of this place, one file per language
- `AGENTS.md` (2.1 čakańnie): the orientation of this place, written by plyn.dojlid
- `miesca.toml` (1.1 asiarodździe): the registry of this place: the answers of its constituents
- `pračytańnie/en.toml` (1.2 miaža): the readings of this place in English
- `śled.toml` (3.2 pierachod): the work of this place, one zapis per krok

## How to check

The tool github_read of the frame's Klučnik, operation check, runs the checks of the system on this place and replays śled.toml through the kernel, the same check that decides the landing; files not yet committed are passed as changes. Its tool github, operation land, lands a branch on main: Plynia checks its head and sets the status pravierka naming the kernel that passed it, and only then main takes it through the gateway; a change that touches what the place's own tests guard carries a trailer `Testy:` saying what ran and its result. Nothing moves this place to a newer kernel: when the kernel lands, it rechecks this place and records the result on its head.

## Norms

The norms of the system hold here as in every place. They are kept once, open to read, in plyn-one/plyn.mova: rejestr.toml holds each norm, the statements of formuła that state it and who decided it, with the definitions and the base its statements read, and pračytańnie/en.toml says what each of them means; read them with the tool github_read. A check that fails names the norm, its statement and a witness, and that is when an agent reads it there in full.

This place adds no norms of its own.

## Where to go

A framework an agent lays pages out with on its first or second try: proportional scaling within a few regimes, as A-Rozum/prastora showed, joined with a closed vocabulary of relations that works at every scale, a manifest that fits in an agent's context, and a check by rendering. Made anew: A-Rozum/prastora and the prototype at plyn-css-proto.pages.dev are sources, not material moved here.

What waits in śled.toml (declarations pending, the kroks possible next) is not kept here: it is read through Klučnik. Start journal work with the tool journal_view, the whole of the line of work as its root: it shows the open cycles of the line, what they read and who works on them now; journal_search and journal_fetch find and return single records. A session's tool list is fixed when it connects, so a session started before a release of Klučnik may lack journal_view or journal_write: it reconnects, or sends the same request with the session pass of git_access, as git does, to POST /git/journal/view to read and POST /git/journal to write.
